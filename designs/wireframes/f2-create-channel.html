F2 — Create a channel (initiator side)

Generate code → share → wait → key exchange → safety phrase → ready. Codes are single-use with a TTL (spec §3.1); the safety phrase is the MITM defense (spec §3.1.5, §9) and is spoken calmly, never dramatically. Edge frames (dashed): code expires unused · safety-phrase mismatch.

They match
They don't match
PurposeThe MITM check (spec §3.1.5), phrased as a two-person ritual, not a warning. Both phones derive the same three words from the shared key material — comparing them out loud proves nobody sat in the middle.
Entry pointsAutomatic from F2.4. The identical screen appears on the joiner's phone (F3.4) with the identical words.
Exit pointsThey match → F2.6. They don't match → F2.8 (edge frame). Destructive option is spaced below primary, never adjacent (foundations).
Edge casesPeers can't talk right now (code was shared on paper, peer is remote) → they can compare over any channel they trust; spec makes verification strongly encouraged, not enforced — this design always shows the screen and offers no skip (flagged as an open product question in the README).

Make a new code
Not now
PurposeThe MITM defense working as designed (spec §3.1.5, §9). Tone stays level: state what it can mean, state what was done (everything discarded), point forward. No sirens, no red.
Entry pointsThey don't match on F2.5 (or on the joiner's F3.4 — both sides land on their own copy of this screen once either declines).
Exit pointsMake a new code → F2.1. Not now → F4. Either way the discarded pairing is unrecoverable — keypairs deleted on both sides.
Edge casesFalse alarm (misread word) → cost is one minute: make a new code. Design accepts false positives cheerfully; the asymmetry (cheap redo vs. silent interception) is the whole point.
