F9 — Paywall (yearly subscription · the permanence guarantee · store-mediated restore)

Creation is gated by an active yearly subscription — unlimited lines while it runs (spec §10). THE PERMANENCE GUARANTEE rides at headline height, never in fine print: every line created while subscribed works forever; a lapse only pauses creating new ones; nothing is ever frozen or repossessed. Joining is free forever and never surfaces this screen. No price exists anywhere outside the stores — the CTA carries the literal {STORE_PRICE} placeholder, rendered at runtime by StoreKit / Play Billing. A calm full-screen page (USER decision) — no account, no email, anywhere. Edge frames (dashed): restore on reinstall · purchase cancelled · lapsed subscription.

[then straight on to F9.4's destination. If the store finds nothing: “The store has no subscription for this account.” — one line under the button, stays on this page, no drama]

PurposeProve the no-account promise survives a reinstall: the store receipt is the only memory anywhere. Restore → native StoreKit / Play Billing receipt check → active again. No email, no login, no “enter the address you bought with” — those things don't exist here. Restore reliability is a top-tier feature: it is the ONLY path to channel creation after reinstall (spec §10).
Entry pointsRestore on F9.2 — typically after reinstall or panic wipe (F8.3), when local entitlement state was destroyed with everything else.
Exit pointsReceipt found → toast “Purchase restored.” → F9.4 (on to creating). Not found (different store account, never bought) → factual one-liner, page stays, {STORE_PRICE} — start remains available.
Edge casesRestore on reinstall (required edge) is this frame. Restore is store-mediated end to end — nimna cannot look the user up, by design. Channels are NOT restored: keys died with the wipe (spec §6.1); only the subscription returns — re-pairing is out-of-band, one new code. Cross-platform: an iOS receipt is invisible to Play Billing and vice versa — switching platforms is a new purchase (spec §10). Store unreachable → “Couldn't reach the store. Try again in a moment.”

PurposeThe permanence guarantee, in UI (spec §10): a lapse gates only the creation of NEW lines. Nothing is frozen, degraded, or repossessed — structurally guaranteed, because channels are keypairs, the relay has no accounts to flag as expired, and entitlement is checked only at creation time on the initiator's device.
Entry pointsThe yearly subscription lapses at the store; the app learns at the next local entitlement check. No push, no email, no in-app announcement marks the moment.
Exit pointsRows → F5 chat, exactly as ever — knock, talk, media, wipe, all of it. “+” → Create a code → F9.2; Enter a code → F3.1, free. Resubscribing on F9.2 resumes creating; nothing needs restoring or thawing.
Edge casesThe lapse must never leak into conversation surfaces: no “renew” toast, no changed captions on lines, no nagging anywhere. Every line created while subscribed remains permanent and fully functional forever — stated as firmly as zero-storage (spec §10). The business model inherits its decency from the architecture.
