Clear
PurposeFail without blame. The canonical error string covers both mistype and expiry honestly, because from this phone they are indistinguishable (see F3.7).
Entry pointsJoin from F3.1 (or a scanned/uploaded QR) when the relay finds nobody on that code's hash.
Exit pointsClear → empty field, try again. Back → F4. No retry limit in UI; the relay throttles rendezvous lookups to stop brute-forcing (spec §4), which never triggers for a human correcting a typo.
Edge casesCode was right but the creator cancelled it → same state, same words; the string's “ask them” hands the pair back to each other. Repeated rapid failures → relay throttling may slow responses; UI stays calm, never mentions “security”. No failed attempt ever notifies anyone, on either side (spec §3.1 silence doctrine).

[keyboard]
Clear
PurposeThe restored §3.1 doctrine, made visible: a device that enters its own active code is blocked client-side, before anything reaches the wire, with copy that says exactly what to do instead — share it. Likeliest arrivals: scanning your own QR to “test” it, or a copy/paste roundtrip of your own share.
Entry pointsCompleting entry (any of the four methods) with a code this device created and still holds — the creator keeps its outstanding codes until finalization (spec §3.1 step 3).
Exit pointsClear → F3.1, empty field. Back → F4. The natural next act lives on the create side: the share sheet on F2.2 (this frame never re-opens it for you — no flow shortcut, just honest words).
Edge casesDoctrine-safe distinctness: the silence doctrine's ONE generic response (F3.6/F3.7) covers foreign codes — the relay-facing failed/expired/used cases. Your own code is local knowledge; this distinct rendering leaks nothing to anyone, and no prober learns anything they didn't already hold. The guard matches only this device's own OUTSTANDING codes: it never detects “a code from someone you already have a line with” — duplicate channels between the same two people are legitimate and structurally undetectable, by design (spec §3.1). Once a code finalizes or expires it leaves the guard set; entering it then gets the ordinary generic response.
