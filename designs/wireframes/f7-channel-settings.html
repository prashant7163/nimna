F7 — Channel settings (label · notifications · receipts · per-channel wipe)

Everything here is per-channel and stored only on this phone (spec §6). Notifications are the one opt-IN — default off, and the caption says exactly what a push contains. Wipe is hold-to-wipe, 1.5 s, release cancels (USER decision).

Hold to wipe

Hold for 1.5 seconds. Let go to keep everything.

Keep
PurposeFast but unmistakable: the hold IS the confirmation — no second dialog. Copy is one breath per sentence, and the honest cross-device note (“their phone keeps its side”) prevents a false belief the UI could never correct later.
Entry pointsWipe this line from F7.1.
Exit pointsHold completes (1.5 s) → channel keys + history destroyed atomically → toast “Channel wiped.” → F4, where the row simply isn't there. Keep or swipe-down → F7.1, untouched.
Edge casesReleased early → cancels — nothing happens, track resets to zero instantly, sheet stays. No partial wipe state can exist (single atomic delete). Wiping while on the line → session drops as the keys vanish; the peer just sees the line go dotted.

‹ Marlowe

Hold to wipe

[finger down: the channel's line burns down right→left while held (here ~0.9 s of 1.5 s). Release at ANY point before the end → cancels, bar snaps back, nothing happens. On completion: the line shrinks from center to two dots, which fade — 480 ms, once]

Keep
PurposeThe USER-locked interaction made visible: destruction requires sustained intent, measured in the same visual language as the product — the line itself burning down.
Entry pointsFinger down on Hold to wipe in F7.2.
Exit pointsHold reaches 1.5 s → wipe executes → toast “Channel wiped.” → F4. Release before 1.5 s → back to F7.2 exactly as it was.
Edge casesAccidental pocket-touch cannot wipe: it takes a deliberate 1.5 s press on a button inside a sheet two taps deep. Interruption mid-hold (call, notification banner) → treated as release → cancel. Haptics tick with the burn; on cancel, one soft settle — never a celebratory buzz for destruction.
