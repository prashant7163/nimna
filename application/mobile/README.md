# nimna — mobile app (Flutter)

The Nimna client for iOS and Android. **Closed source.** Implements the
protocol in [`docs/nimna-protocol-spec-v0.1.1.md`](../../docs/nimna-protocol-spec-v0.1.1.md);
all UI is bound by the artifacts in [`designs/`](../../designs/) (tokens,
components, wireframes, hi-fi screens, voice guide) — implemented, never
reinterpreted.

**Status:** Session 1 scaffold. `lib/main.dart` is a placeholder shell; the
real app shell, navigation, and encrypted local storage arrive in Session 7.

## Identifiers

- Dart package: `nimna` · applicationId / bundle ID: `app.nimna`
  (CODE decision; freely changeable until the first store upload).
- App name renders as lowercase **nimna** per the locked brand.

## Layout

- `lib/` — Dart source (placeholder `main.dart` only, for now)
- `test/` — widget/unit tests (`flutter test`)
- `android/`, `ios/` — platform shells generated by `flutter create`
  (platforms limited to iOS + Android; no web/desktop)

## Commands

```sh
flutter pub get       # fetch dependencies
flutter analyze       # static analysis (must be clean)
flutter test          # run tests
flutter run           # launch on a connected device/simulator
```

## Standing rules (see repo-root CLAUDE.md)

- No third-party crash/analytics/telemetry SDKs, ever.
- Dependencies minimal and boring; every addition justified and pinned.
- Local diagnostic log only: encrypted, ring-buffered, events/error-codes
  only — never content, keys, codes, tokens, or peer identifiers.
- Crypto primitives are locked in Session 2; nothing hand-rolled.
- i18n: EN/DE/FR/ES/IT at launch. Every user-facing string via ARB/l10n
  from the first widget (zero hardcoded strings, enforced from Session 7);
  layouts survive German-length strings; the EN voice guide fixes canonical
  meaning for all translations.
